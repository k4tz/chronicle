# Chronicle — Development Plan for Claude Code

> Long-form novel writing app powered by local LLMs.
> Target: 200,000–400,000 word novels. Text stories only. Local-first.

---

## Stack

| Layer | Choice |
|---|---|
| Frontend | React 18 + TypeScript + Tailwind CSS + Vite |
| State | Zustand + React Query (TanStack Query v5) |
| Backend | Node.js + Express + TypeScript |
| ORM | Drizzle ORM (SQLite locally → PostgreSQL when deployed) |
| Cache | lru-cache (Redis-ready via swappable CacheService) |
| LLM | Abstracted LLMService — supports Ollama locally, OpenAI/Anthropic remotely |
| Search | SQLite FTS5 (built-in, no extra deps) |
| Export | docx + pdfkit + epub npm packages |

---

## Drizzle Quick Reference

> New to Drizzle? Read this — it covers everything used in this project.

**Define a table** in `server/src/db/schema.ts`:
```typescript
import { sqliteTable, text, integer } from 'drizzle-orm/sqlite-core'

export const projects = sqliteTable('projects', {
  id:        text('id').primaryKey(),        // set in code with nanoid()
  title:     text('title').notNull(),
  createdAt: text('created_at').notNull(),   // ISO string: new Date().toISOString()
})
```

**Query** from anywhere in `server/src/`:
```typescript
import { db } from '../db'
import { projects } from '../db/schema'
import { eq } from 'drizzle-orm'

const project = await db.select().from(projects).where(eq(projects.id, id)).get()
await db.insert(projects).values({ id: nanoid(), title: 'My Novel', createdAt: new Date().toISOString() })
await db.update(projects).set({ title: 'New Title' }).where(eq(projects.id, id))
await db.delete(projects).where(eq(projects.id, id))
```

**Migration commands** (run from `server/`):
```bash
npx drizzle-kit generate    # generate SQL from schema changes
npx drizzle-kit migrate     # apply pending migrations to DB
npx drizzle-kit studio      # open browser DB explorer
```

**SQLite to PostgreSQL**: only `server/src/db/index.ts` and `drizzle.config.ts` change. Schema file stays identical.

### Phase 3 — Style Module
**Goal**: Author defines writing style via sample uploads; LLM extracts a Style Profile.

Tasks:
- [ ] Style Profile table in schema (name, uploadedSamples as JSON text, extractedProfile as JSON text)
- [ ] Sample upload endpoint (save files to `server/data/samples/`)
- [ ] LLM style extraction prompt → returns structured StyleProfile JSON
- [ ] Style Profile editor (view + manually adjust extracted attributes)
- [ ] Style preview: paste neutral paragraph → LLM rewrites in this style
- [ ] Multiple profiles per project
- [ ] Style drift monitor: score a completed chapter against its profile (0–100)

StyleProfile shape (stored as JSON text in DB, parsed in app):
```typescript
interface StyleProfile {
  sentenceLengthTendency: 'short' | 'medium' | 'long' | 'varied'
  metaphorDensity: 'sparse' | 'moderate' | 'rich'
  vocabularyRegister: 'simple' | 'literary' | 'archaic' | 'contemporary'
  pacingRhythm: 'slow-burn' | 'moderate' | 'fast-paced'
  dialogueToNarrationRatio: number  // 0.0 = all narration, 1.0 = all dialogue
  descriptionDensity: 'minimal' | 'moderate' | 'immersive'
  povIntimacy: 'distant' | 'close' | 'deep'
  internalMonologue: 'none' | 'occasional' | 'frequent'
  voiceProfileStub: null  // reserved for future audio/TTS
  notes: string
}
```

Acceptance: Upload 3 writing samples, extract a profile, preview it on a test paragraph.

### Phase 5 — Context Assembly Engine
**Goal**: Smart prompt assembly that fits within token budgets for any local LLM.

Tasks:
- [ ] `ContextAssemblyEngine` service in `server/src/services/contextAssembly.ts`
- [ ] Tiered context model:
  - Tier 1 (always in): premise, genre, tone, active character names + one-line states (~1000 tokens)
  - Tier 2 (chapter-relevant): full profiles of characters/locations in this chapter (~3000 tokens)
  - Tier 3 (recent narrative): compressed summaries of last 3 chapters (~2000 tokens)
  - Tier 4 (on-demand): KB lookup available to LLM mid-generation
- [ ] Relevance scorer: rank KB entries by entity overlap + recency + arc involvement
- [ ] Context budget manager: fill tiers in order, stop at model context limit
- [ ] Compression pass: LLM summarizes overlong entries on first use; cache the result
- [ ] Token counter: character-based estimate (1 token ≈ 4 chars) + 20% safety buffer
- [ ] Context preview panel in chapter editor (shows author exactly what LLM will see)
- [ ] Prompt templates at `server/src/prompts/*.md`

Acceptance: For a 13B model with 8192 context window, assembled context fits within 5000 tokens.

- [ ] ChapterVersion record saved for every pass + every manual save

- [ ] Post-generation: entity extraction, snapshot prompt, KB update
- [ ] Generation queue: queue multiple chapters, process in background
- [ ] SSE streaming endpoint: `GET /api/chapters/:id/generate/stream`

Acceptance: Full 2000-word chapter generated through all 4 passes, KB updated afterward.

## Service Interfaces

All interfaces live in `server/src/types/services.ts` and are imported by their implementations.

### LLMService
```typescript
export interface GenerationRequest {
  systemPrompt: string
  userPrompt: string
  model?: string
  temperature?: number
  maxTokens?: number
}

export interface LLMService {
  generate(req: GenerationRequest): AsyncGenerator<string>    // streaming
  complete(req: GenerationRequest): Promise<string>           // single response
```

## Context Assembly (Tier System)

```
Token budget = model_context_limit - generation_headroom (default headroom: 4096 tokens)

Tier 1 — Core (~1000 tokens, always included):
  Project premise + genre + tone + POV rule
  Active character names + one-line current states

Tier 2 — Chapter-relevant (~3000 tokens):
  Full profiles of characters appearing in this chapter
  Full profiles of locations in this chapter
  Active plot threads for this chapter

Tier 3 — Recent narrative (~2000 tokens):
  Compressed summaries of last 3 chapters
  World state changes from the last confirmed snapshot

Tier 4 — On-demand (not injected; available as a lookup):
  KB search endpoint the LLM can call mid-generation
  Only used if the model supports function/tool calling
```

## Key Implementation Notes

1. **JSON in SQLite**: All JSON fields are stored as text. Call `JSON.parse()` and `JSON.stringify()` in the service layer — never in route handlers.

2. **IDs**: Use `nanoid()` for all primary keys. Generate them in application code before inserting, not auto-generated by the DB.

3. **Timestamps**: Store as ISO 8601 strings (`new Date().toISOString()`). Works identically in SQLite and PostgreSQL with no driver surprises.

4. **Streaming**: Use Server-Sent Events (SSE) for all generation passes. Express supports this natively — set `Content-Type: text/event-stream` and write chunks with `res.write()`. Save partial content every 500 tokens to survive crashes.

5. **Token counting**: Use a character-based estimate (1 token ≈ 4 chars) plus a 20% safety buffer. No tokenizer library needed — good enough for context budget management.

6. **Context assembly**: Implement as a pure function `assembleContext(projectId, chapterConfig) → AssembledContext` that takes data as arguments. Easier to test and reason about than a stateful class.

7. **Prompt templates**: Load `.md` files from `server/src/prompts/` at startup and cache in memory. Use simple string replace for `{{variable}}` substitution. Add a `POST /api/prompts/reload` endpoint for hot-reload during development.

8. **Story Bible export**: Iterate all KB entities and build the docx using the `docx` npm package. Do not call the LLM — this is a direct structured export of existing data.

9. **Frontend routing**: React Router v6 with nested routes. Each module gets its own segment: `/projects/:id/world`, `/projects/:id/characters`, `/projects/:id/chapters/:chId`, etc.

10. **Error boundaries**: Wrap each major page in a React error boundary so one broken module does not crash the whole app.

11. **Optimistic updates**: Use React Query's optimistic update pattern for CRUD so the UI feels instant.

12. **CORS**: Add the `cors` npm package to Express. In development, allow `http://localhost:5173`. In production, serve the built client from Express or configure a reverse proxy.

### Switching to PostgreSQL (deploy)

1. Set `DATABASE_URL=postgresql://user:pass@host/dbname` in `server/.env`
2. In `server/`: `npm install postgres`
3. In `server/src/db/index.ts`: swap in the PostgreSQL driver (commented block already there)
4. In `server/drizzle.config.ts`: change `dialect` to `'postgresql'`
5. Run `npx drizzle-kit generate && npx drizzle-kit migrate`
6. Schema file does not change.
